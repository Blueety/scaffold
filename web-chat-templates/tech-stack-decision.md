# 技术栈决策对话模板

> 在网页 AI 中讨论和确定技术栈时用这个模板。
> 位置：**project-kickoff 之后、frontend-design 之前**。也可以直接在聊天里问，不必走模板。

---

## 提问模板

```
我的项目需求：
- [简述项目]
- [核心功能]
- [特殊要求，如离线、实时、国际化等]

请推荐技术栈。分两组——**难换的**和**好换的**：

难换的（定错了要动数据或动外部对接）：
1. 数据库（关系型 / 文档 / KV）
2. 查询层（ORM / query builder / 裸 SQL）
3. 认证与授权（自建 / 托管服务商 / 平台自带）
4. 文件与对象存储
5. 缓存
6. 队列或后台任务

好换的（换掉基本只动一层）：
7. 语言
8. 框架
9. 包管理器
10. 测试工具
11. 部署方式

每个选择说明：
- 为什么选它
- 主要替代方案是什么
- 什么情况下应该换
- **锁定成本**：以后换掉它要动什么——数据迁移？外部对接重签？还是只改一层代码？
```

## 追问模板

```
这几个方案各有什么优缺点？
我这种规模的项目，哪个最省事？
如果以后要加 [某功能]，哪个框架扩展性更好？
哪个方案的学习成本最低？
```

## 对比表格模板

让 AI 输出对比表格：

```
请用表格对比这几种方案：
| 维度 | 方案 A | 方案 B | 方案 C |
|---|---|---|---|
| 开发速度 | | | |
| 学习成本 | | | |
| 社区生态 | | | |
| 扩展性 | | | |
| 部署复杂度 | | | |
| **锁定成本**（换掉要动什么） | | | |
```

## 最终确认

```
我决定用 [你的选择]。

请帮我确认：
1. 需要安装哪些依赖
2. 项目初始化命令是什么
3. 基本目录结构长什么样
4. 开发/测试/构建分别用什么命令

输出要简洁，我直接复制到终端执行。
```

## 记下来

把整份抄成下面这个块。**这是全仓库唯一一份「技术栈决定」块**——`WORKFLOW.md` 只留指针，不复写。两个去处：整块写进项目 `README.md` 的「技术栈」段；其中「难换的」六项按 ADR 三条准入写进 `docs/adr/`：

```
技术栈决定：
- 数据库: PostgreSQL（托管 Supabase）
- 查询层: Prisma
- 认证与授权: Supabase Auth
- 存储: Supabase Storage
- 缓存: 无（先不加）
- 队列: 无（先不加）
- 语言 / 框架: TypeScript + Next.js
- 包管理: pnpm
- 测试: Vitest + Playwright
- 部署: Vercel
```

「难换的」那六项，就算结论是「先不用」，也写出来——**「我们决定现在不需要缓存」本身就是一条决策**，不写下来，三个月后有人会以为你漏了。
