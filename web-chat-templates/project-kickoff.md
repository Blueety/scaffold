# 项目启动对话模板

> 第一次和网页 AI 聊新项目时用这个模板。
> 覆盖：想法、目标用户、核心功能、需求细化、验收标准、边界。

---

## 开场白

```
我想做一个新项目，帮我理清思路。

项目名称（暂定）:
一句话描述:
目标用户:
核心场景（用户会怎么用）:
必须有的功能:
一定不做的功能:
我已有的技术能力:
部署方式（本地/网页/手机）:
```

## 需求细化

当 AI 给出初步方案后，追问具体需求：

```
帮我把这个功能拆成具体需求：
1. 用户会怎么操作
2. 每步操作的输入和输出是什么
3. 什么情况算成功
4. 什么情况算失败
5. 边界条件是什么
```

## 验收标准

需求理清后，让 AI 写验收标准：

```
请帮我写出这个功能的验收标准：

格式：
- Given（在什么条件下）
- When（用户做什么操作）
- Then（应该发生什么）

给出至少 3 个正常场景和 2 个异常场景。
```

## 追问模板

```
这个方案的主要风险是什么？
有没有更简单的替代方案？
MVP（最小可用版本）应该先做哪些功能？
哪些功能可以放到第二期？
如果只能做一件事，应该先做哪个？
```

## 结束前确认

```
请把我们讨论的结果整理成：
1. 项目一句话描述
2. 核心功能列表（按优先级排序，不超过 5 个）
3. 明确不做的功能
4. 验收标准（Given/When/Then 格式）
5. 技术约束
6. 术语表：讨论中出现的关键词，每个一句话定义，并指出容易混淆的近义词
7. 我们聊过但排除掉的方案，以及排除理由
8. 我明确要求反着常规来的地方，以及理由

第 6、7、8 项会被写进项目仓库长期维护，请写得能独立看懂，不要用「上面提到的那个」。

不要写代码。
```
