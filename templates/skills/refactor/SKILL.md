# 重构

> 适用于类型轴 = 重构的任务：**行为不变，只改结构**。

## 安全网（动手之前必须有的东西）

重构的判据是「行为不变」。**没有能证明行为没变的测试，就没有判据**——你只是改完看着还行。

1. **相关路径有能跑通的测试吗？** 有就直接用。
2. **没有就补 characterization test**：把代码**当前的实际行为**记下来，不是你以为它该有的行为。
   - 输入输出、边界值、异常路径各来一条
   - 古怪行为也要锁住——它可能是有人在依赖的既有行为
   - 这类测试的期望值来自**实跑结果**：跑一遍，把输出记下来当期望值
3. 安全网跑绿之后，才开始改结构。

**跑不了的测试不是安全网。** 慢、flaky、要人工参与的，先按 `skills/bug-fix/SKILL.md` 的「把回路收紧」处理。

## 发现行为其实不对怎么办

**停下来。** 那不是重构，是修 bug 或加功能——转去对应的 skill，别混在一个改动里。

混在一起的代价：diff 里既有结构变化又有行为变化，审查时分不清哪处是故意的，回滚也没法只回滚一半。

## 循环

一次一小步，每步跑一次安全网：改一小块结构 → 跑安全网 → 绿就继续，红就改回去。

不要「全部改完再跑测试」——那时候已经分不清是哪一步弄坏的。

## 什么算「结构」

- 抽函数 / 内联、改名、搬移
- 消除重复、拆长函数、把散落的逻辑收拢
- 换内部数据表示（不换对外形状）
- 引入 seam（接口位置）以便将来替换实现

判据：**调用方看得见的东西不变**——对外签名、错误模式、不变量、可观察输出，一个都不动。

## 不要顺手做的事

- 不要顺手加功能，哪怕一行
- 不要顺手改与结构无关的格式（那是 lint 的事）
- 不要顺手升级依赖
- 不要在没有安全网的区域动刀

## 批量机械改动：审查对象不是 diff

同一个替换落到很多处（改名、统一调用形式、替换某个字面量）时，**diff 是最差的审查材料**：改对了，几百个 hunk 长得一样；改错了，错误也长得一样。审查对象换成「生成这批改动的机制」。

先按形态分三档，不要混：

| 形态 | 什么时候 | 审查什么 |
|---|---|---|
| **逐点** | 位置就一两处，每处能用唯一锚点定位 | diff（普通 T2 / T3 流程） |
| **元组清单** | 位置已完整枚举，每处就是「某行上的某段确定字节」 | 元组清单 + 应用器的拒绝行为 |
| **脚本** | 真需要正则 / AST 匹配，无法完整枚举 | 脚本本身 + 在整本副本上的演练结果 |

### 元组清单的契约

一条元组是 `(file, line, old, new)`：

- `old` 从**未截断的**源码里复制，且在那一行里**恰好出现一次**。出现两次以上说明这一行不适用元组，改用逐点——恰好一次这条规则本身就是「这一行会不会改歪」的探针。
- `(file, line)` 唯一：同一行两条元组一律不许，拆成逐点。两条落在同一行时，`old` 和 `new` 互相包含的写法会让应用顺序改变结果。
- `old` / `new` 里不许有换行；含 TAB 的行不适用（制表符是语义的时候尤其）。
- **整批要么全写，要么一个字节都不写**：应用器先校验完全部元组，任何一条不匹配（文件不在、行越界、`old` 不唯一）就整批拒绝，不允许部分写入。允许部分写入的应用器不算数——它只是把 diff 藏起来了。
- 同一文件内按**行号降序**应用，这样即使某处改动改变了行数，后面待应用的元组也不会错位。

### 脚本形态的演练

脚本和应用器都是**一次性的**，放本任务目录的 `work/`（`${TMPDIR:-/tmp}/<项目名>/<任务目录名>/work/`，见 `AGENTS.md`），不进项目，收尾时随 `work/` 一起删。审查者会读它们和演练输出，但**报告里不许引用它们的路径**——要留的东西先进 `evidence/`。写完后先在项目的整本副本上演练，六项都要有实际输出：

1. 清单里每个目标都变了
2. 清单外没有文件被改
3. 列出的边界情况都覆盖到了
4. 副本能通过 `docs/commands.md` 里对应的构建 / 测试命令
5. 同一脚本重跑不会二次改写
6. 改动文件数、改动次数与清单一致

演练通过后，把**脚本、清单、演练输出**交给独立审查者——它审「这个机制会不会改错东西」，不是审 diff 好不好看。轮次上限同样 2 轮，超了阻塞；**不许把脚本形态降级成元组清单**去绕过审查。

## 和别的 skill 的分工

- **`skills/tdd/SKILL.md`**：加新行为时用（红 → 绿）。重构**不在**那个循环里，但重构需要它产出的测试当安全网。
- **`skills/bug-fix/SKILL.md`**：行为要变时用。重构途中发现行为不对，转过去。
- **`skills/pre-review/SKILL.md`**：改完之后审查。Standards 轴看结构是不是真的变好了（重复代码 / 发散式变化 / 霰弹式修改这类坏味道）。

## Output

- 安全网是什么：哪几个测试 / 命令，补了哪些 characterization test
- 结构改了什么，以及**行为没变**的证据（安全网跑绿的实际输出）
- 顺带发现的行为问题（如果有）——单列，不在这次改
