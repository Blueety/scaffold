### 横切约定（有对外 HTTP 接口时填，没有就整节删掉）

<!-- 这几条是审查时的硬判据——pre-review 的 Standards 轴会来查这里。 -->

- **URL 命名**：名词不用动词（`/getUsers` ❌ → `/users` ✅）；用复数；小写 + 连字符；最多 3 层；过滤条件走查询参数
- **HTTP 方法**：GET 查 / POST 建 / PUT 全量改 / PATCH 部分改 / DELETE 删。注意**幂等性**——GET/PUT/DELETE 幂等，POST 不幂等，需要防重复提交
- **状态码**：200/201/204 成功；400 参数错；401 未认证（你是谁）；403 无权限（你能做什么）；404 不存在；5xx 服务端错。**不要所有错误都返回 200**——缓存层会把它当成功缓存，监控也发现不了
- **错误响应**：统一结构；`message` 要说清哪个参数错了、为什么；**绝不返回调用栈或 SQL**
- **响应结构**：所有接口用同一种外层结构（不要 `data` / `result` / `content` 混用），前端才能统一封装请求层
- **版本控制**：要不要 `/v1/`？旧版本至少维护多久？
- **分页**：用什么参数、返回什么字段
