# 命令说明

> 列出项目所有验证命令。Agent 完成修改后必须运行相关命令。

## 快速检查

| 命令 | 用途 | 什么时候跑 |
|---|---|---|
| `<test 命令>` | 单元测试 | 改了函数逻辑 |
| `<lint 命令>` | 代码风格 | 每次修改后 |
| `<typecheck 命令>` | 类型检查 | 改了类型定义或接口 |

## 完整检查

| 命令 | 用途 | 什么时候跑 |
|---|---|---|
| `<full test 命令>` | 完整测试套件 | 提交前 |
| `<build 命令>` | 构建 | 提交前 |
| `<e2e 命令>` | 端到端测试 | 改了用户流程 |
| `<visual 命令>` | 视觉回归（截图基线 diff） | 改了样式 / 布局 |
| `<a11y 命令>` | 可访问性（axe-core 等） | 改了 UI 结构 |

## 何时跑什么

| 改动类型 | 必须运行 |
|---|---|
| 单函数修改 | 针对性单元测试 |
| API 行为变更 | 相关集成测试 |
| UI 变更 | 构建 + 视觉回归（截图基线）+ 可访问性检查 |
| 认证/支付/数据迁移 | 完整检查 + 人工审查 |

## UI 变更怎么验

「构建 + 手动看」是最弱的一档，尽量别停在这。可机器判定的手段（按性价比排）：

| 手段 | 判据 | 变红条件 |
|---|---|---|
| 截图基线 | `toHaveScreenshot()` / pixelmatch 与基线 diff | 渲染结果变了 |
| 对比度 | WCAG 相对亮度公式，正文 ≥ 4.5:1 | 低于阈值 |
| 溢出 / 尺寸 | `scrollWidth > clientWidth`、触控目标 ≥ 44px | 超出阈值 |
| 一致性 | 扫描硬编码色值 / 间距 / 字号（应全部来自 token） | 出现散值 |
| 可访问性 | axe-core 规则集 | 违反规则 |

**截图不需要 GUI**——Playwright / Puppeteer 的无头模式直接截。

多模态模型可以用来看截图、提示「哪里看着不对」，但它是**发现该写什么断言的工具，不是断言本身**：结论不确定、不可重复，同一个截图问两遍可能不一样。它可以当筛查，不能当闸门。
