### Windows 上 `bash scripts/check-gates.sh` 根本没跑到脚本

- **现象**: 输出一串 `?????`，退出码 1——看着像「闸门有违规」，其实命令没执行到脚本
- **原因**: PATH 里排第一的 `bash.exe` 是 `C:\Windows\System32\bash.exe`（WSL 的桩），它不认识 Windows 路径
- **解决**: 在 Git Bash 里跑 `bash scripts/check-gates.sh`；或在 PowerShell 里用 Git 自带的 sh：`sh scripts/check-gates.sh`（**只在 sh 真是 bash 时**——Ubuntu 的 `/bin/sh` 是 dash，这个脚本用不了）

### PowerShell 里 `git commit` 的闸门提示是乱码

- **现象**: 提交被钩子拦下，但 `check-gates.sh` 的中文提示显示成 `闂搁棬妫€鏌ュけ璐ワ細`，看不出挂了哪一条
- **原因**: 钩子里的脚本按 UTF-8 输出，PowerShell 按控制台的 ANSI 代码页（中文系统是 936 / GBK）解码。管道里没有这个问题，只有写进控制台才会
- **解决**: 在按 UTF-8 渲染的终端里提交——Git Bash 里直接 `git commit -m "..."`；非要用 PowerShell，就先把控制台切到 UTF-8（`chcp 65001`）**再重开** PowerShell

### 中文标点放进 awk 方括号，Windows 上会把中文切成半个字节

- **现象**: 归属检查在本地全绿，GitHub 的 Windows runner 上却静默失配——闸门读到的路径是 `src/` 加一个乱码字节，判定「没有相关文件改动」
- **原因**: awk 的方括号表达式**按字节比较**，`[（(]` 的集合是 `{E3,80,88,28}`，而「我」是 `E6 88 91`——第一个 `88` 就命中，截断点落在汉字中间。Linux / macOS 的 awk 在该位置按字符匹配，所以本机复现不出来
- **解决**: 多字节字符一律用**字面量**比较，不进方括号：末尾标点用 `sub(/，$/, "")` 这类逐字面量剥离，括号 / 冒号用 `index()` 定位或先归一成半角再走纯 ASCII 正则。判定器里有静态闸门（`gate-test` 的 `G-mb`）盯着这条
